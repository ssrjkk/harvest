02

Что это и что умеет

Один проход пайплайна auto.py — четыре фазы: генерация/переиспользование кошельков → кран → фарм → экспорт. Поведение каждого кошелька детерминировано его адресом, поэтому перезапуск не «палит» ферму сменой паттерна.

Кошельки

Генерация и хранение

BIP-39 через eth_account, импорт/экспорт CSV/JSON, шифрование сид-фраз AES-256-GCM мастер-ключом, дедупликация, защита от CSV-инъекций, атомарная запись файлов.

Кран

Пополнение балансов

Стратегии chainstack / direct / web, pre-flight валидация живых стратегий, retries, rate-limit, прокси-ротация, ensure_balance до target_balance. Нет живых стратегий — включается force_farm.

Фарминг

Асинхронный воркер-пул

Один NetworkManager на сессию, чанки по chunk_size, crash recovery через state.json, динамическое число воркеров по здоровью RPC, адаптивные веса падающих действий.

Анти-сибил

Профили поведения

Активность, паузы, суммы с джиттером, газ, время суток (днём −25%, ночью +150% к пропуску), «отдых» на N циклов, staggered-старт, burst-всплески ×1.6.

RPC

Живучий сетевой слой

Мульти-RPC со списком, EMA-скоринг нод, ротация на лучшую, zombie-воскрешение первым успехом, circuit breaker, адаптивный token-bucket, wait_for_receipt с бюджетом и failover.

Портал

Веб + Telegram

aiohttp-дашборд: метрики, старт/стоп/пауза, история циклов, топ кошельков, экспорт с ключами. Бот на long-polling: те же команды + /doctor, /history, /export. Сессии HMAC, default-deny.

Что будем фармить?

Фарм — это автоматические учебные транзакции в тестовой сети. Деньги ненастоящие, всё бесплатно и безопасно.

Какой масштаб?

Кошельки создаются сами. Для первой пробы хватит 5–10.

Один круг — это проход по всем кошелькам: кран, потом транзакции.

Кран — бесплатная раздача тестовых монет. Выключите, только если монеты уже есть.

Пояснение фаз

Команда выполняет 4 фазы run_once: добор кошельков → pre-flight крана и request_batch → FarmerPool (чанки, воркеры, crash recovery) → export_csv/json. Повтор запуска продолжает state.json с места обрыва.

Тестнеты only. Генерация — WebCrypto; адрес выводится из ключа локально (ethers через CDN, при офлайне — демо-режим с честной пометкой). Ничего не отправляется в сеть.

08

Безопасность — по умолчанию закрыто

Шифрование

Сиды — AES-256-GCM (nonce 12B, AAD wallet-seed). Файлы экспорта — AES-256-CBC v2: PBKDF2-SHA256 100k, раздельные ключи шифрования и MAC, HMAC-проверка до записи.

Redaction

RPC-URL чистятся везде: credentials до @ и query-токены стираются. https://user:pass@host/?api_key=X → https://host/. Логи, история циклов, CLI-вывод.

Fail-closed

Нет мастер-ключа при шифрованных сидах — отказ. Портал default-deny, single-instance лок на БД, ограничение прав файлов, лимиты логина 5/10мин per-IP.

Нашли уязвимость — не открывайте публичный issue. Используйте private vulnerability reporting на GitHub или напишите мейнтейнеру. Поддерживается только последний релиз; ответ в течение 48 часов.

Тесты и вопросы

  • wait_for_receipt: EMA-бюджет поллинга, failover при серии ошибок, деградация частоты, None по бюджету без отката nonce, кросс-чек на вторичной ноде.
  • Линт: ruff · flake8 · black (120) · mypy · bandit. CI-бейдж в README.
Q1 Это для мейннета?
Нет. Только тестнеты и учебный фарминг активности. Не используйте реальные средства и не храните реальные ключи в демо-зоне сайта.
Q2 Где мои ключи из демо-генератора?
Только в памяти вашей вкладки. Сайт статический, отправки на сервер нет — закройте вкладку или нажмите «Очистить», и они исчезнут. Для постоянного хранения используйте экспорт и шифрование из Python-версии.
Q3 Что делать с 0x0-контрактами в конфиге?
Это заглушки по дизайну: валидатор пропускает их с замечанием, runtime делает фоллбэк на transfer. Впишите реальные адреса из Tier-2 документации, когда будете готовы.
Q4 Почему пульт пустой?
Пульт оживает после первой публикации: запустите python publish_dash.py на машине фермы (по расписанию — каждые 15–60 минут, история master не растёт — снапшот уходит в ветку gh-pages). До этого вся остальная информация и инструменты уже работают.
